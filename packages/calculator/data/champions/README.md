# 챔피언스 포켓몬·폼 / 특성 / 습득 기술 카탈로그

2026-11-17 기준으로 고정한 Pokémon Showdown의 `champions` 원본에서 실제 추출한 데이터다. 계산은 설치된 `@smogon/calc@0.12.0`에 맡기고, 엔진에 없는 **전체 특성 선택지·습득 기술 연결·추가 입력 분류·출처**를 파일로 보완한다. 웹 입력 UI나 계산 지원 범위를 확대한 작업은 아니다.

## 원본과 적용 범위

- 원본: [smogon/pokemon-showdown](https://github.com/smogon/pokemon-showdown/tree/f827a1d41064e0dec4c19c6ea0394fcf0c23479c), 커밋 `f827a1d41064e0dec4c19c6ea0394fcf0c23479c`(2026-11-16 UTC).
- 등장 여부: 원본의 챔피언스 데이터에서 `exists && num > 0 && !isNonstandard`인 포켓몬·기술을 사용한다. OU/Uber 등 대전 등급으로 거르지 않는다.
- 전투 중 폼은 `battleOnly`에 지정된 변신 전 포켓몬 중 하나 이상도 등장해야 포함한다. 일반 플라엣테가 미등장이어도 플라엣테 영원의꽃이 등장하는 경우처럼, `baseSpecies`만으로 제외하지 않는다.
- 특성 슬롯: [기본 도감](https://github.com/smogon/pokemon-showdown/blob/f827a1d41064e0dec4c19c6ea0394fcf0c23479c/data/pokedex.ts)의 일반·숨겨진·특수 슬롯을 챔피언스 모드로 해석한다.
- 습득 기술: [챔피언스 learnsets](https://github.com/smogon/pokemon-showdown/blob/f827a1d41064e0dec4c19c6ea0394fcf0c23479c/data/mods/champions/learnsets.ts)를 `Dex.mod('champions').species.getMovePool(id, false)`로 읽는다. 메가진화·폼의 기술 상속은 원본 Dex가 해석한다. 진화 전 기술 목록을 임의로 합치지 않는다.
- 색·무늬 등 외형 차이도 보존한다. 아래 382개는 도감 번호가 서로 다른 포켓몬 382종이라는 뜻이 아니다.
- 이 원본은 커뮤니티 구현이다. 공식 게임의 현재 등장 목록·특성·기술을 게임 화면으로 전수 대조한 데이터가 아니며, 랭크 시즌별 참가 가능 여부나 기술·특성·이벤트의 조합 적법성을 보장하지 않는다.
- 원본 카탈로그의 영어 이름과 정규화한 ID는 유지한다. 포켓몬·폼 한글명은 `smartnuo-comparison.json`의 `pokemonFormCatalog[].nameKo`, 특성 한글명은 `abilityCatalog[].nameKo`로 연결한다. 포켓몬·폼 382개·특성 216개를 모두 보관하며, 비교 사이트의 관찰 이름인 `siteName`과 공식 표기로 보완한 표시명을 구분한다. 화면·문서용 기술 한글명은 별도 [move-names.ko.json](move-names.ko.json)의 `moves[id].name`으로 연결한다. 이미지 연결은 포함하지 않았다.

종족값·타입·위력·타입 상성 등 계산용 기본 데이터 전체를 중복 저장하지 않는다. `moves.json`의 515개는 원본의 전체 등장 기술 목록이며, 현재 포켓몬 중 습득자가 없는 기술도 포함한다. 변화기도 전체 습득 목록에 보존하고, 데미지 선택창 노출 여부는 별도로 결정한다.

기술 한글명은 PKHeX에 보존된 게임 텍스트의 고정 커밋을 기술 번호로 연결하고, 챔피언스 전용 기술 명칭 자료와 515개 모두 대조했다. 계산 규칙·등장 여부는 이 명칭 원본에서 가져오지 않는다. 기존 PokéAPI 표기의 `깨뜨리다`·`탐내다`는 이번 기준의 `깨트리기`·`탐내기`로 연결한다. `Last Resort`는 `비장의무기`, `Torch Song`은 `플레어송`, `Rock Blast`는 `록블라스트`로 표시한다. 명칭 파일 추가는 전체 기술 선택 UI의 구현을 의미하지 않는다.

한글명 재생성·검증에는 기존과 동일한 고정 Showdown 원본과 명칭 텍스트가 필요하다. 두 입력 모두 SHA-256을 확인한 뒤 기술 번호를 한글명에 연결한다.

```sh
node packages/calculator/scripts/extract-move-names-ko.mjs --archive /path/to/pinned-showdown.tar.gz --names-file /path/to/text_Moves_ko.txt --check
```

`pokemon.json` 주요 필드는 다음과 같다.

```text
id / name / nationalDexNumber / baseSpeciesId / forme
cosmetic / battleOnly / changesFrom / requiredItemIds
abilities[]: slot / id / name / hidden / special
moveIds[]: 원본 등장 여부를 확인한 습득 기술
excludedMoveIds[]: 원본 습득 목록에는 있지만 미등장인 기술(현재 결과는 모두 빈 배열)
learnsetSourceSpeciesIds[] / learnsetSource[]: 기술 목록을 상속받은 종과 원본 위치
engineId / engineMapping: 계산 엔진의 종 ID와 연결 방식
source[]: 원본 파일 경로와 시작 줄
```

원본 기술 풀은 `moveIds`와 `excludedMoveIds`의 합집합으로 복원한다. 특정 포켓몬의 기술과 특성을 선택할 때는 이 포켓몬의 목록으로 제한하고, 엔진의 전체 사전을 그대로 선택 목록으로 사용하지 않는다.

### 정적 데이터 일치로 확인할 수 없는 동작

- **성묘:** 같은 묘두기 → 메가 메타그로스 조건에서 `alliesFainted`를 0과 2로 바꿔도 설치 엔진의 데미지는 모두 `42~50`이었다. 이는 엔진 동작 실험이며 게임 실측 기대값이 아니다. 현재 챔피언스 계산 분기에서 이 횟수가 위력에 반영되지 않는 공백을 확인했다.
- **분노의주먹·토해내기:** 받은 타격 횟수·비축 횟수를 연결할 입력 계약과 계산 검증이 필요하다. 데이터에 기술이 있다고 바로 지원으로 표시하지 않는다.
- **심록 등:** 엔진은 실제 HP로 발동 여부를 판정한다. 입력한 시작 HP를 유지하며 효과만 켜는 제품의 토글을 지원하려면 별도 변환과 검증이 필요하다.
- **반복 공격:** 도구 소모, HP 변화, 벽·필드 제거, 폼 변화, 기술 사용 후 랭크 변화는 후속 타격을 바꿀 수 있다. 첫 공격의 난수 배열을 반복해 더하는 것만으로 지원을 보장할 수 없다.

기존 지진 기준 사례 검증을 다른 기술·특성 전체의 정확성으로 확대하지 않는다. 이번 카탈로그의 모든 기술·특성에는 `calculationVerification: "not-verified-by-catalog-extraction"`을 기록했다.

당시 실행기는 제거했으며 460개 결과와 해시를 조사 이력으로 보존한다. 후속 [조건부 입력 감사](CONDITIONAL-AUDIT.md)는 추출 단계의 표시와 별도로 관리한다. 추가 입력 대상 기술 33개·특성 17개 전체에 164개 조건 사례를 실행해 엔진 반영 20개, 일부 반영 6개, 해당 조건 계산 없음 15개, 앱의 성공 조건·복사 결과 판정 필요 8개, 싱글 발동 맥락 없음 1개로 구분했다. 이전 보류 80개도 296개 조건 대조를 완료했다. 엔진 반영 10개, 일부 반영 49개, 조건 미반영 9개, 사건·위임 처리 9개, 싱글 맥락 없음 1개, 직접 데미지 계약 밖 2개이며 이번 범위의 미완료는 0개다. 제품 입력·전달과 엔진 조건 공백은 동시에 존재할 수 있다.

## 조건부 입력 분류

기술명으로 입력·기본값·예외를 찾으려면 [조건부 기술 처리 규칙](CONDITIONAL-MOVE-RULES.md)을 참고한다.

2026-11-19 제품 규칙은 `conditions.json`의 `productRules`와 기술·특성별 `classification`에 연결한다. 생성 원본은 `scripts/champions-product-rules.mjs`다. 원본 게임 기전, 제품에서 받을 입력, 실제 계산 구현 상태를 구분한다.

- `ruleIds`, `mechanicInputIds`, `mechanicReviewRuleIds`: 원본 기전과 엔진 진단에 필요한 문맥. 기존 130개 항목·460개 조건의 검증 범위를 보존한다.
- `requiredInputIds`, `productRuleIds`, `productPolicy`: 최신 제품 입력과 지원·제외·1회 결과 규칙. 제외한 항목의 입력은 비우고, 진단용 입력을 화면에서 요구하지 않는다.
- `definitionInputIds`: 공통 조건 정의의 입력 참조. 기술별 최종 입력은 `requiredInputIds`를 사용한다. 객기·병상첨병 등의 `status`·`targetStatus`는 포켓몬에 이미 입력한 상태이상을 참조한다. 별도 기술 전용 토글은 없다.
- `calculationVerification`과 `productPolicy.implementation`: 분류 갱신을 계산 구현·검증 완료로 표시하지 않는다.

## 재생성·검증

게임 업데이트를 반영할 때는 `source-pin.json`의 Showdown 커밋과 아카이브 해시를 새 원본에 맞춘 뒤 아래 추출기를 실행한다. `engine-diff.json`과 이전 커밋의 차이에서 새 폼·특성·습득 기술과 엔진 누락을 확인한다. 같은 원본 플래그를 사용하는 부자유친 제외 기술과 내던지기 도구 보정은 재생성된다. 새 기술명은 한글명 추출기로 검증하고, 새 포켓몬·폼·특성의 한글명은 별도 연결표를 보완한다.

신규 발동 조건은 제품 규칙과 계산 사례를 추가해 검증한다. `@smogon/calc` 버전을 올릴 때는 `patches/`의 보정이 새 엔진에도 필요한지 회귀 테스트로 확인하고 패치와 잠금 파일을 함께 갱신한다.

프로젝트의 Node.js·pnpm 버전과 설치된 의존성을 사용한다. 원본 아카이브는 저장소에 포함하지 않는다.

```sh
curl -L --fail 'https://codeload.github.com/smogon/pokemon-showdown/tar.gz/f827a1d41064e0dec4c19c6ea0394fcf0c23479c' -o /tmp/champsparty-showdown.tar.gz
pnpm catalog:extract --archive /tmp/champsparty-showdown.tar.gz
pnpm catalog:extract --archive /tmp/champsparty-showdown.tar.gz --check
```

추출기는 아카이브 SHA-256·엔진 버전을 먼저 검사한다. 고정 원본을 임시 디렉터리에 풀고, 이미 설치한 TypeScript로 원본 Dex를 읽은 뒤 자체 임시 디렉터리만 제거한다. Showdown 서버 패키지를 설치하거나 웹 번들에 포함하지 않는다. 생성 JSON은 추출기가 서식을 관리하므로 손으로 수정하지 않는다. 기전 분류는 `scripts/champions-conditions.mjs`, 제품의 입력·처리 결정은 `scripts/champions-product-rules.mjs`에서 수정한 뒤 다시 추출한다.

당시 회귀 검사는 원본·생성 파일 해시, ID 중복·정렬, 전체 특성·기술 참조, 출처 줄, 엔진 연결·버전, 분류의 입력 일관성, 전투 중 폼의 제외, 일반·메가 한카리아스의 특성·기술 상속을 다룬다. `--check`는 원본에서 다시 생성한 폼 별칭·내던지기 도구 보정·부자유친 제외 기술을 포함한 아홉 JSON의 바이트 일치를 검사한다. 이 검증은 공식 게임 데이터 전수 확인이나 각 기술의 독립 데미지 검증을 대신하지 않는다.

2026-11-17 추출과 2026-11-18 상태 변화 후속 검증에서 Node.js `26.13.1`·pnpm `12.19.0`으로 다음을 실제 통과했다.

- 당시 검사에서 카탈로그 무결성·참조·분류·엔진 버전을 확인했다.
- 원본 아카이브를 다시 읽는 `catalog:extract --archive … --check`: 여섯 JSON 모두 동일.
- 당시 회귀 테스트 46개가 통과했다. 조건부 입력 164사례·상태 변화 296사례를 다시 계산하고, 고정 원본에서 감사 JSON·보고서를 재생성해 일치 여부를 확인했다.
- `pnpm lint`, `pnpm typecheck`, `pnpm format:check`, `git diff --check` 통과.

이번 변경은 웹에서 새 카탈로그를 불러오지 않으므로 브라우저 선택 UI와 이 데이터 전체의 계산은 실행 검증하지 않았다.

추출 원본의 MIT 고지는 `UPSTREAM-LICENSE.txt`에 보존했다. 이 고지는 포켓몬 이름·이미지 등 별도 권리에 대한 사용 허락을 뜻하지 않는다.
