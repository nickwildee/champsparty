## 1. 프로젝트의 목적

포켓몬 챔피언스를 잘 아는 사용자가 실전용 포켓몬의 능력치를 세부 조정하면서, 자신이 지정한 여러 상대에 대한 스피드·공격·방어 결과를 한눈에 확인하는 계산기다.

사용자는 대비할 상대와 조건을 직접 선택한다. 내 포켓몬의 노력치 등을 수정하면 현재 입력 조건의 결과가 즉시 갱신된다. 게임을 실행할 수 없는 상황에서도 세팅을 구상할 수 있도록 한다.

프론트엔드 취업용 프로젝트로서는 입력과 상태 관리, 계산과 화면 갱신, 서버 데이터 저장, 인증, 반응형 사용성, 테스트와 성능 개선을 실제 필요에 따라 다룬다. AI가 많은 구현을 수행하더라도 사용자가 선택 이유와 핵심 동작을 이해하고 설명하는 것이 목표다.

## 2. 대상 사용자와 사용 환경

- 대상은 포켓몬 배틀과 세팅에 익숙한 사용자다.
- 주된 사용 시점은 파티 구성과 실전용 세팅 준비 단계다.
- PC를 핵심 사용 환경으로 삼고, 모바일에서도 입력과 결과 확인이 편리하도록 만든다.
- 시각적 장식보다 입력량, 수정 동선, 정보의 가독성을 우선한다.
- 지원 게임은 포켓몬 챔피언스로 한정한다. 다른 게임·세대를 선택하는 UI는 현재 범위에 없다.

## 3. 핵심 기능

### 3.1 세 가지 계산 영역

| 영역   | 계산 방향                                | 핵심 출력                                                |
| ------ | ---------------------------------------- | -------------------------------------------------------- |
| 스피드 | 내 포켓몬과 각 상대의 최종 스피드 비교   | 스피드 실수치, 빠름·동속·느림                            |
| 공격   | 내 포켓몬이 선택한 기술로 각 상대를 공격 | 대미지 범위, 쓰러뜨리기까지의 타수와 확률                |
| 방어   | 각 상대의 선택한 기술로 내 포켓몬을 공격 | 받는 대미지 범위, 내 포켓몬이 쓰러지기까지의 타수와 확률 |

- 내 포켓몬 세팅은 세 영역에서 공유한다.
- 각 영역은 별도의 상대 목록을 갖는다.
- 상대는 영역별로 0~5마리까지 추가할 수 있다. 처음부터 5개 입력 폼을 채우도록 요구하지 않는다.
- 상대 추가 버튼으로 포켓몬을 고른 뒤 능력치와 관련 조건을 입력한다. 추가한 상대는 수정하거나 제거할 수 있다.
- 노력치 등의 입력을 바꾸면 현재 조건의 계산 결과를 갱신한다.
- 변경 전후 결과를 따로 비교하거나 이전 결과를 자동 이력으로 보관하는 기능은 현재 요구사항에 포함하지 않는다.

### 3.2 입력 조건

- 내 포켓몬과 상대 포켓몬의 종류, 노력치, 성격, 특성, 도구 등 계산에 필요한 조건을 입력한다.
- 공격에서는 내 포켓몬의 기술을, 방어에서는 각 상대의 기술을 선택한다.
- 랭크 변화는 포켓몬별로 입력할 수 있다.
- 날씨 등 계산에 필요한 필드 조건을 입력할 수 있다. 필드 조건의 공유 범위와 상세 폼 구성은 입력 계약을 정할 때 확정한다.
- 공격·방어 계산의 시작 HP는 100%로 고정한다.
- 능력치 입력 단위, 유효 범위, 총량 제약과 엔진 입력으로의 변환은 챔피언스 지원 데이터와 함께 확인한다. 다른 게임의 수치를 확인 없이 적용하지 않는다.

### 3.3 결과의 의미

- 표시 목적은 현재 세팅의 결과를 보여 주는 것이다. 입력을 바꿔도 계산 결과가 같다면 같은 결과를 표시한다.
- 공격·방어에서는 확정 또는 난수에 따른 KO 타수와 확률, 대미지 범위를 제공한다.
- KO 확률은 선택한 동일 기술을 N회 사용해 모두 명중했을 때, 대미지 난수에 따라 N회 이내에 상대를 쓰러뜨릴 확률이다. 명중률, 급소 발생 확률, 부가효과 발생 확률을 하나의 성공 확률로 합산하지 않는다.
- 결정력과 내구 지표도 제공한다. 정확한 공식, 단위와 반영할 보정은 아직 확정하지 않았다.
- 스피드는 수치의 빠름·동속·느림을 비교한다. 모든 전투 행동의 순서를 시뮬레이션하는 기능으로 확대하지 않는다.
- 결과에서 대표로 보여 줄 타수의 선택, 확률 표시 자릿수, 근사 결과의 처리와 반복 공격 시 지원할 상태 변화는 계산 입력·출력 계약에서 확정한다.

## 4. 회복 효과와 도구의 범위

- 자뭉열매, 먹다남은음식 등 회복 효과를 포함한 전투 진행 계산은 MVP에서 제외한다.
- 이후 진행한 엔진 기능 조사는 지원 가능성을 확인한 것이다. 회복 효과를 다시 MVP에 넣기로 결정한 것은 아니다.
- 도구 입력 자체는 제공한다. 도구별로 어떤 효과를 계산에 반영하는지 지원 범위를 분명하게 한다.
- 슈캐열매 등 반감열매는 첫 공격의 대미지 감소와 반복 공격 중 소모 처리를 구분해서 검증해야 한다. 현재 문서는 반복 공격의 정확한 처리가 확인되었다고 보장하지 않는다.
- 엔진에 빠진 처리를 보완할 수 있다는 가능성과, 실제 추가 구현 범위가 승인되었다는 사실을 구분한다.

## 5. 저장과 로그인

### 5.1 두 종류의 저장

| 구분                   | 저장하는 내용                                                  | 저장 위치와 목적                                   |
| ---------------------- | -------------------------------------------------------------- | -------------------------------------------------- |
| 명시적으로 저장한 세팅 | 내 포켓몬의 세팅                                               | 계정에 연결해 저장하고 PC·모바일에서 불러오기      |
| 자동 복원할 작업 화면  | 편집 중인 내 세팅, 영역별 상대와 계산 조건 등 마지막 작업 상태 | 브라우저 로컬 저장으로 같은 환경에서 작업 이어가기 |

- 로그인 제공자는 네이버를 우선 사용한다.
- 계정에 저장한 세팅의 저장·불러오기는 로그인한 사용자에게 제공한다.
- 계산 기능 전체를 로그인 뒤에만 사용할 수 있게 만드는 요구사항은 없다.
- 상대 목록이나 전체 파티를 명시적 저장 대상으로 확장하지 않는다.
- 명시적 저장은 사용자가 저장 동작을 했을 때 반영한다. 실험 중인 입력 변경이 계정에 저장한 기준 세팅을 자동으로 덮어쓰지 않는다.
- 브라우저의 작업 초안을 기기 간에 자동 동기화하는 기능은 현재 범위에 없다.

### 5.2 저장 세팅을 불러올 때

1. 사용자가 목록에서 불러올 세팅을 직접 선택한다.
2. 선택한 세팅을 현재 내 포켓몬 입력에 적용한다.
3. 각 영역에 입력한 상대 목록은 유지한다.
4. 적용된 현재 입력을 기준으로 결과를 갱신한다.

- 불러오기 전 입력하던 모든 포켓몬을 별도 이력으로 자동 보관하지 않는다.
- 저장 목록을 백그라운드에서 다시 조회하더라도 편집 중인 입력을 덮어쓰지 않는다.
- 작업 화면의 로컬 복원이 끝났는지 확인한 뒤 자동 저장을 시작한다. 기본 입력값이 먼저 저장되어 이전 작업을 지우는 상황을 방지한다.

## 6. 화면 방향

- PC에서는 내 포켓몬 입력과 상대별 결과를 함께 확인하고 수정할 수 있는 구성을 기본 방향으로 삼는다.
- 내 입력을 한쪽에 두고 스피드·공격·방어 영역을 전환하는 방식으로 시작한다. 세부 폭과 배치는 화면 설계에서 확인한다.
- 상대는 세팅 요약과 결과를 쉽게 확인하고, 필요한 경우 상세 입력을 열 수 있게 구성한다.
- 모바일에서는 내 세팅 수정과 상대 결과 확인에 필요한 스크롤과 반복 동작을 줄이는 방향으로 설계한다.
- 스타일링은 Tailwind CSS를 사용한다. 상세 와이어프레임과 계산기 컴포넌트 구성은 아직 확정하지 않았다.

### 6.1 포켓몬 이미지와 운영 방침

- 포켓몬 이미지는 [PokéAPI Sprites](https://github.com/PokeAPI/sprites)의 `other/official-artwork` 정적 PNG를 사용하는 방향으로 정했다. 이미지 연결 코드는 아직 적용하지 않았으며, 지원 포켓몬과 메가진화·리전폼의 매핑은 구현 단계에서 확인한다.
- 학습 및 정보 제공을 위한 비상업적 팬 프로젝트로 운영한다. 비상업적 목적, 포켓몬 권리자, 공식 승인·후원·제휴 관계 부재와 이미지 출처·권리 안내 링크를 표시할 예정이다. 고지 UI는 아직 적용하지 않았다.
- 이미지에 대한 개별 사용 허락은 확인되지 않았다. 비상업 운영·출처·권리자 고지를 사용 허락이나 저작권 문제 해소의 근거로 기록하지 않는다. 선택 이유와 남은 제약은 DECISIONS.md의 D16에 기록한다.

## 7. 현재 제외한 기능

- 파티 추천, 취약점 보고서, 자동 노력치 배분 추천
- 변경 전후 비교 화면, 자동 변경 알림, 과거 입력의 자동 이력 관리
- 배틀 중 현재 HP를 입력하는 전투 진행 시뮬레이션
- 회복 효과를 포함한 턴별 전투 재현
- 전체 파티나 상대 목록의 명시적 계정 저장
- 작업 초안의 기기 간 자동 동기화
- 챔피언스 외 게임·세대 지원
- 첫 버전에서 네이버와 카카오 로그인을 모두 제공하는 것

## 8. 현재 기술 방향

아래는 구현 방향이며 설치·연동 완료 목록이 아니다. 선택 이유와 대안은 DECISIONS.md를 참고한다.

| 구분             | 방향                                                             |
| ---------------- | ---------------------------------------------------------------- |
| 애플리케이션     | Next.js + TypeScript                                             |
| 저장소           | pnpm 워크스페이스, `apps/web`과 `packages/calculator` 구성 완료  |
| 웹과 서버 기능   | `apps/web`에 화면, 인증과 저장 관련 서버 기능 배치               |
| 계산 로직        | `packages/calculator`에서 입력·계산·결과 처리, 브라우저에서 실행 |
| 대미지 엔진      | `@smogon/calc` 활용                                              |
| 작업 입력 상태   | React `useReducer`, 작은 UI 상태는 필요에 따라 `useState`        |
| 계산 결과        | 현재 입력에서 파생                                               |
| 서버 저장 데이터 | TanStack Query로 조회·갱신 상태 관리                             |
| 저장소 DB        | 로컬 PostgreSQL 18.7 구성·직접 접속 검증 완료, Drizzle 연결 예정 |
| 인증             | 네이버 로그인, Better Auth 연동 방향                             |
| 스타일링         | Tailwind CSS, PostCSS 연동 완료                                  |
| 기본 검사        | TypeScript 타입 검사, ESLint, Prettier 구성 완료                 |

- 별도 API 서버는 초기 구성에 두지 않는다. 분리할 구체적인 필요가 생겼을 때 검토한다.
- Node.js `26.13.1`(26 LTS), pnpm `12.19.0`, Node.js 버전 관리 도구 fnm을 사용한다. `.node-version`과 루트 `package.json`에 버전을 기록했고, 새 로그인·대화형 zsh에서 자동 전환과 워크스페이스 인식을 확인했다.
- 실행 환경의 실제 설치 버전은 Next.js `16.4.6`, React·React DOM `19.3.0`, TypeScript `5.9.3`, Tailwind CSS `4.3.3`, ESLint `10.15.0`, Prettier `3.10.1`이다. 재설치 기준은 루트 `pnpm-lock.yaml`이다. 계산 엔진 등 후속 기능의 패키지 버전은 아직 정하지 않았다.
- 로컬 PostgreSQL의 직접 접속·인증·권한은 검증했다. 앱의 pg·Drizzle 연결과 Better Auth 실제 로그인·세션 흐름은 아직 구현·실행 검증하지 않았다.
- App Router, `src/`, 웹 내부 별칭 `@/*`, Turbopack을 사용한다. React Compiler와 Cache Components는 이번 단계에서 활성화하지 않았다. 기존 루트 협업 지침을 사용하도록 Next.js의 지침 파일 자동 생성은 껐다.
- 계산 패키지는 TypeScript 원본을 공개하고 웹이 `workspace:*` 의존성으로 가져온다. Next.js가 코드를 변환하므로 계산 패키지의 별도 빌드는 두지 않는다. 자세한 이유와 호환성 보정은 DECISIONS.md의 D14에 기록했다.
- DB 접속 환경변수는 아래 로컬 구성에 기록했다. 인증용 환경변수, 실제 계산 입력·출력 계약과 상세 테이블 구조는 후속 기능 설계에서 확정한다.

## 9. MVP 확인 기준

다음은 합의한 기능에서 도출한 확인 항목이다. 아직 통과한 항목으로 기록하지 않는다.

1. 챔피언스에서 지원하기로 정한 포켓몬과 계산 조건을 입력할 수 있다.
2. 스피드·공격·방어 영역에서 공통 내 세팅과 영역별 상대 목록을 사용할 수 있다.
3. 상대를 필요한 만큼 추가·수정·제거할 수 있고 영역별 최대 5마리 제한이 적용된다.
4. 현재 입력 변경이 결과에 반영되며, 대미지 범위와 KO 타수·확률을 정의한 의미대로 표시한다.
5. 합의한 공식으로 결정력·내구 지표와 스피드 실수치를 표시한다.
6. 회복 효과 제외 등 계산의 지원 범위가 결과 해석과 일치한다.
7. 네이버 로그인과 내 세팅의 계정 저장·불러오기가 동작한다.
8. 로컬 작업 복원, 저장 세팅 불러오기와 서버 데이터 갱신이 합의한 입력 유지 규칙을 지킨다.
9. PC와 모바일에서 주요 입력·계산·저장 흐름을 사용할 수 있다.
10. 대표 계산 사례와 핵심 사용자 흐름을 검증하고, 실제 측정 결과를 개선의 기준으로 남긴다.

첫 배포 플랫폼, 일정, 구체적인 성능 목표 수치는 아직 정하지 않았다. 숫자를 임의로 완료 조건에 추가하지 않는다.

### 로컬 PostgreSQL 구성

- [인증 상위 이슈 #7](https://github.com/nickwildee/champsparty/issues/7)의 첫 작업인 [#8](https://github.com/nickwildee/champsparty/issues/8)에서 Homebrew PostgreSQL `18.7`을 구성했다. 데이터 디렉터리는 `/opt/homebrew/var/postgresql@18`이며 포트 `5432`의 루프백 주소와 `/tmp` 소켓으로 접속한다. macOS 로그인 시 자동 실행은 등록하지 않았다.
- DB 이름은 `champsparty`이고 소유자는 `champsparty_migrator`다. `champsparty_app`은 실행 중인 앱용, `champsparty_migrator`는 테이블 구조 변경용이다. 두 역할 모두 슈퍼유저·DB 생성·역할 생성 권한이 없다.
- `public`에는 서비스 테이블을, `drizzle`에는 후속 마이그레이션 이력을 둔다. 두 스키마의 소유자는 migrator다. 앱은 DB 접속과 `public` 사용만 허용하며, migrator가 `public`에 만드는 테이블에는 조회·추가·수정·삭제 권한을 자동 부여한다. 앱의 테이블·스키마·임시 테이블 생성, 구조 변경·삭제, `drizzle` 접근과 migrator 역할 전환은 허용하지 않는다.
- 두 프로젝트 역할에는 IPv4·IPv6·Unix 소켓 모두 `scram-sha-256` 인증을 적용했다. DB 이름을 바꿔 인증 규칙을 우회하지 못하도록 모든 DB에 같은 규칙을 적용한다. 기존 `heoknoh` 관리 접속의 `trust` 규칙은 보존했다. 원본 설정은 `/opt/homebrew/var/postgresql@18/pg_hba.conf.champsparty-before-scram`에 보관한다.
- 서로 다른 64자 무작위 비밀번호를 사용한다. 앱의 `DATABASE_URL`은 `apps/web/.env.local`, migrator의 `MIGRATION_DATABASE_URL`은 `apps/web/.env.migrations.local`에 저장했다. 두 파일은 권한 `0600`이고 Git에서 제외된다. Next.js는 `.env.local`을 읽지만 마이그레이션 전용 파일의 로딩은 후속 작업에서 별도로 구성한다. 비밀값은 문서·이슈에 기록하지 않는다.
- 직접 검증 40개 항목이 통과했다. 두 역할 × 세 접속 경로에서 정상·오류·누락 비밀번호의 18개 경우, 다른 DB 이름을 통한 우회 거부 2개, 앱 권한 거부 9개, 자동 데이터 권한·migrator의 구조 변경 등을 확인했다. 검증용 테이블은 제거했으며 실제 인증·이력 테이블은 아직 없다.
- 서버 중지 후 수동 재실행, 두 역할의 재접속과 잘못된 비밀번호 거부를 확인했다. 최종 상태는 실행 중이며 자동 실행 미등록, HBA 구문 오류 0개다. 이 단계에서 앱 의존성은 추가하지 않았으며 Drizzle 마이그레이션과 실제 네이버 로그인은 검증 범위가 아니다. 선택 이유와 제약은 [D17](DECISIONS.md#d17-로컬-postgresql과-서비스마이그레이션-역할-분리)에 기록했다.

| 명령                                                                                                      | 용도                                                             |
| --------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| `brew services run postgresql@18`                                                                         | 필요할 때 실행. 로그인 시 자동 실행은 등록하지 않음              |
| `brew services stop postgresql@18`                                                                        | 서버 중지                                                        |
| `brew services info postgresql@18 --json`                                                                 | 실행 상태와 자동 실행 등록 여부 확인                             |
| `/opt/homebrew/opt/postgresql@18/bin/pg_isready -h 127.0.0.1 -p 5432`                                     | 서버의 접속 수락 상태 확인. 계정 인증 검증과는 별개              |
| `/opt/homebrew/opt/postgresql@18/bin/psql -h 127.0.0.1 -p 5432 -U champsparty_app -d champsparty -W`      | 앱 역할로 접속. 비밀번호는 명령 인자가 아닌 숨겨진 입력으로 전달 |
| `/opt/homebrew/opt/postgresql@18/bin/psql -h 127.0.0.1 -p 5432 -U champsparty_migrator -d champsparty -W` | 구조 변경 역할로 접속                                            |

접속 후 `SELECT current_database(), current_user, version();`과 `SELECT 1;`로 대상 DB·역할·버전과 쿼리 실행을 확인할 수 있다. 다음 인증 작업은 [#9의 pg·Drizzle 연결과 서버 환경변수 구성](https://github.com/nickwildee/champsparty/issues/9)이다.

### pg·Drizzle 연결 설계 — #9, 구현 전

- pg 연결 풀을 같은 서버 실행 환경에서 재사용한다. 로컬 시작값은 최대 연결 10개, 연결 획득 대기·새 연결 생성 제한 5초, 유휴 연결 정리 10초다. SQL 실행 시간 제한이나 배포용 최적값의 검증을 뜻하지 않는다.
- 개발 모드의 `globalThis`에 풀을 보관한다. DB 접속 정보·풀 설정을 바꾸면 개발 서버를 재시작한다. DB 모듈은 `server-only`로 표시한다.
- `DATABASE_URL` 누락은 DB 기능을 처음 사용할 때 검사한다. DB 오류는 호출부에 전달하고 공통 코드에서 Next.js를 강제 종료하거나 작업을 자동 재시도하지 않는다. 유휴 연결 오류도 처리하며 실제 URL·비밀번호는 로그에 넣지 않는다.
- 터미널 명령은 `@next/env`로 개발 환경 파일을 읽고 앱과 같은 연결 코드를 사용한다. 읽기 쿼리로 `SELECT 1`, DB `champsparty`·역할 `champsparty_app`을 확인한다. 확인용 공개 API나 테이블은 만들지 않는다.
- 패키지 설치·연결 모듈·접속 확인 명령은 아직 구현·실행 검증하지 않았다. 버전·파일 배치·실행 구성의 구체화와 설치·검증은 별도 구현 단계에서 다룬다. 이유·대안·제약은 [D18](DECISIONS.md#d18-앱-db-연결과-검증-방식)에 기록했다.

### 인증 기본 구조 — #10 이후, 구현 전

- 네이버 단일 로그인을 사용하고 별도 이메일·비밀번호 가입·복구·이메일 인증과 로그인 외 네이버 API 기능은 추가하지 않는다.
- `user`는 Better Auth 기본 7개 필드만 사용한다. `emailVerified`는 라이브러리·제공자 기본 처리에 맡기고 추가 인증이나 임의 변경은 하지 않는다. `account`는 별도 기본 모델을 유지한다.
- 이메일 누락 시 처리, 제공자 토큰 보관·갱신, 세션 유지·갱신 기간과 쿠키 캐시, IP·User-Agent 저장은 아직 미정이다. 7일 유지·1일 갱신은 제안이며 확정 설정이 아니다.
- 향후 계정 저장 세팅은 `user.id`와 연결하는 방향이다. 세팅 저장 테이블·API는 현재 인증 연결 범위에 포함하지 않는다. 네이버 앱 등록, 인증 테이블·마이그레이션과 실제 로그인·세션 검증은 아직 하지 않았다. 상세 경계는 [D19](DECISIONS.md#d19-네이버-단일-로그인과-인증-데이터의-기본-구조)에 기록했다.

### 코드 위치와 실행 방법

| 위치                               | 역할                                                          |
| ---------------------------------- | ------------------------------------------------------------- |
| `apps/web/src/app`                 | 페이지·공통 레이아웃과 브라우저 연결 확인 컴포넌트            |
| `packages/calculator/src/index.ts` | 계산 패키지의 공개 진입점. 현재 `add`는 연결 확인용 임시 함수 |
| 루트 `package.json`                | 패키지별 작업 명령 실행과 저장소 전체 Prettier 관리           |

프로젝트 폴더에서 fnm이 `.node-version`에 맞는 Node.js를 선택한 뒤 아래 명령을 실행한다. 새 환경에는 먼저 해당 Node.js·pnpm 도구를 준비해야 한다.

| 명령                             | 역할                                                                        |
| -------------------------------- | --------------------------------------------------------------------------- |
| `pnpm install --frozen-lockfile` | 기록된 lockfile을 변경하지 않고 의존성 설치                                 |
| `pnpm dev`                       | 개발 서버 실행, 기본 주소 `http://localhost:3000`                           |
| `pnpm typecheck`                 | 계산 패키지와 웹의 타입 검사. 웹은 먼저 `next typegen`으로 라우트 타입 생성 |
| `pnpm lint`                      | 두 패키지의 ESLint 검사, 경고도 실패로 처리                                 |
| `pnpm format`                    | 저장소의 코드·설정·문서 서식 자동 수정                                      |
| `pnpm format:check`              | 수정 없이 서식 검사                                                         |
| `pnpm build`                     | 내부 계산 패키지 코드를 포함한 웹 프로덕션 빌드                             |
| `pnpm start`                     | `pnpm build` 후 프로덕션 서버 실행                                          |
| `pnpm -r list --depth -1`        | 루트와 두 패키지의 워크스페이스 인식 확인                                   |

`next-env.d.ts`는 Next.js가 생성한다. 개발 서버를 처음 실행하기 전에도 `pnpm typecheck`가 필요한 타입 파일을 준비한다. `.next/`, `next-env.d.ts`, `*.tsbuildinfo`와 개인 `.codex/` 설정은 Git에서 제외하며 lockfile은 추적한다.

### 이번 단계의 검증과 한계

- Node.js `26.13.1`·pnpm `12.19.0` 환경에서 웹·계산 패키지 인식, 로컬 의존성 연결, 타입 검사·린트·빌드를 확인했다.
- `pnpm install --frozen-lockfile`, `pnpm format:check`, `pnpm peers check`도 통과했다. lockfile 안의 앱 의존성 문서에서 두 패키지와 내부 링크를 확인했다.
- 개발·프로덕션 페이지의 브라우저 상호작용으로 내부 패키지 함수 실행을 확인했고, Tailwind의 Flexbox·여백·버튼 색상 적용 및 브라우저 경고·오류가 없는 상태를 확인했다. 프로덕션 페이지 HTTP 응답은 200이었다.
- 샌드박스 안의 첫 빌드는 Turbopack의 내부 포트 사용이 막혀 실패했다. 실패 때의 `.next` 캐시를 지우고 권한 제한 밖에서 같은 `pnpm build`를 실행하자 통과했다. 이 실행 환경의 제약과 앱 오류를 구분한다.
- 연결 확인용 `add` 함수와 페이지는 실제 포켓몬 계산 계약·성능·게임 규칙 검증을 대신하지 않는다.

## 11. 문서 유지

- 버전 0.2에서는 기획과 기능 범위를 유지하고, 초기 저장소 설정·문서 인계·개발 도구 설치와 실행 검증 결과를 갱신했다.
- 버전 0.3에서는 워크스페이스·Next.js·Tailwind·검사 도구의 구성, 실행 방법과 실제 검증 결과를 반영했다.
- 버전 0.4에서는 학습 대화·일반 개념 설명·승인 경위를 제외하고, 설치 오류의 원인·해결 내용과 검증 결과를 유지했다. 협업 지침은 공통 원칙 v1.2를 적용한다.
- 버전 0.7에서는 PokéAPI 공식 일러스트를 사용하는 방향, 비상업적 운영과 권리 고지 계획, 조사 결과와 권리상 한계를 기록했다. 이미지·고지 코드는 미적용 상태다.
- 버전 0.10에서는 로컬 PostgreSQL의 설치·수동 실행, 두 역할·스키마·자동 권한, SCRAM 인증·비밀값 보관과 실제 검증 결과를 반영했다. 앱 연결·마이그레이션·로그인은 후속 작업이다.
- 버전 0.11에서는 앱 DB 연결 풀·환경변수·오류·재시도·터미널 검증 설계와 네이버 단일 로그인·인증 기본 구조를 기록했다. 설치·구현·실행 검증과 세션 등 남은 선택은 구분한다.
- 기능 범위나 현재 상태가 바뀌면 승인된 범위에서 이 문서를 갱신한다.
- 중요한 이유와 대안은 DECISIONS.md에 남긴다.
- 현재 기획과 이전 아이디어가 다르면 최신 합의를 적용한다. 과거의 모바일 우선, 상대 10마리, 파티 취약점 보고서 등의 아이디어로 현재 범위를 바꾸지 않는다.
